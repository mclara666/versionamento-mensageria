Objetivo da atividade
Criar um Diário de Aprendizagem Versionado.
Registrar o conteúdo aprendido em cada aula em arquivos Markdown (.md).
Usar VS Code, Git e GitHub durante o processo.
O repositório funciona como uma linha do tempo da aprendizagem.
📁 Organização do projeto
Deve existir um único repositório para a disciplina.
Exemplo: versionamento-mensageria-2026
Não criar um repositório novo para cada aula.
Organização por bimestre e semana:
3-bimestre/semana-15/aula-01.md
4-bimestre/semana-XX/aula-01.md
Também podem existir pastas para atividades e projeto-final.
📝 Registro de cada aula

O arquivo Markdown deve conter:

Tema da aula
O que aprendeu
Conceitos principais
Comandos utilizados
Explicação dos comandos
Atividade prática
Dificuldades encontradas
Resumo final de 3 a 5 linhas

⚠️ O resumo deve ser escrito com suas próprias palavras, demonstrando que você entendeu o conteúdo.

💻 Processo com Git
Criar e salvar o arquivo no VS Code.
Usar git status para verificar alterações.
Usar git add para colocar o arquivo na Staging Area.
Usar git commit para registrar a versão.
Usar git log para consultar o histórico.
Usar git push para enviar ao GitHub.
🔄 Fluxo principal do Git

Working Directory → git add → Staging Area → git commit → Repositório Local → git push → GitHub.

💬 Mensagens de commit
Devem explicar claramente o que foi alterado.
Exemplos:
docs: adiciona resumo da semana 15 aula 01
fix: corrige descrição do comando git commit
Evitar mensagens genéricas como:
teste
atividade
final
pronto
🌐 Conferência no GitHub
Depois do git push, é necessário acessar o GitHub.
Conferir se o arquivo foi realmente publicado.
O trabalho não está concluído apenas porque o git push funcionou.
📸 Print obrigatório

O print do VS Code deve mostrar, sempre que possível:

VS Code aberto;
Estrutura das pastas;
Arquivo Markdown;
Parte do conteúdo;
Terminal;
Evidência do versionamento.

Exemplo de evidência: git status mostrando “nothing to commit, working tree clean”.

📤 Entrega

Na Sala do Futuro, é obrigatório enviar:

Print do Visual Studio Code
Link do repositório no GitHub
Informações da semana, aula e localização do arquivo.
✅ Checklist

Antes de entregar, verificar:

Criou a pasta e o arquivo .md;
Escreveu o resumo com suas palavras;
Salvou o arquivo;
Executou git status;
Executou git add;
Fez git commit;
Usou uma boa mensagem de commit;
Executou git push;
Conferiu no GitHub;
Tirou e anexou o print;
Colocou o link correto do repositório.
